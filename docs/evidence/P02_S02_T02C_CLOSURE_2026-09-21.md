## 3. What was delivered

The domain layer of `@ineractive/product-graph` now carries privacy semantics on the `datapolicy`
node kind:

- closed v1 vocabularies for collection source (`user-provided`, `system-generated`, `imported`,
  `derived`), user visibility (`internal-only`, `user-visible`, `public`), consent (`not-required`,
  `required`, `policy-driven`), redaction (`none`, `sensitive-fields`, `all-fields`), and
  minimization (`unspecified`, `required`);
- the optional free-form processing-purpose list, so purposes stay product-specific instead of a
  fabricated business taxonomy;
- enum registration for all new attributes, so an out-of-vocabulary value fails closed as
  `DOMAIN_INVALID_ENUM_VALUE`;
- three governance-phase rules: `DOMAIN_CONSENT_WITHOUT_USER_VISIBILITY`,
  `DOMAIN_MISSING_REDACTION_CONTROL`, and `DOMAIN_PUBLIC_VISIBILITY_OF_CLASSIFIED_DATA`.

Rules evaluate declared vocabulary values only. A malformed value produces exactly one complaint,
so a document never receives both a schema violation and a derived semantic complaint for the same
offending value.

## 4. No compliance claim

No jurisdiction-specific rule is encoded, and the Grain records that constraint as an explicit
safety requirement. Jev's independent `compliance_overreach` judgment on the exact diff returned
