## 3. What was delivered

The domain layer of `@ineractive/product-graph` now carries data-classification and data-lifecycle
node semantics:

- a closed v1 data-classification vocabulary (`public`, `internal`, `personal`, `sensitive`,
  `secret`, `regulated`) taken from `docs/canonical/PRODUCT_GRAPH.md` §3, with the
  `docs/canonical/RUNTIME_AND_SECURITY.md` §15 privacy list mapped onto it rather than introduced as
  a second competing taxonomy;
- closed v1 lifecycle vocabularies for retention, deletion, export, audit, and residency;
- deterministic `dataclass` and `datapolicy` domain node kinds with declared required and optional
  attribute fields, leaving every existing node kind contract unchanged;
- a data-driven enum-field table and the stable node-phase error code
  `DOMAIN_INVALID_ENUM_VALUE`, which fails closed instead of coercing or dropping an
  out-of-vocabulary value;
- the stable node-phase error code `DOMAIN_LIFECYCLE_CONTRADICTION` for a policy that declares
  bounded retention with no accepted deletion path (absent field or explicit `none`).

The module doc records explicitly that declaring a data class or a lifecycle policy is a
product-semantics statement and is never a legal or regulatory compliance claim
(`docs/canonical/GENERATED_PRODUCT_CONTRACT.md` §9, `docs/canonical/SUPABASE_PLATFORM.md` §17.1).
