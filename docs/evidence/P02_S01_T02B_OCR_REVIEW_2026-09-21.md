## 1. Why delegation mode is the correct OCR execution layer here

The repository designated Alibaba OCR as its AI review engine in P00, but the hosted
semantic layer needs a scoped LLM endpoint that does not exist in this environment. OCR
ships a first-class execution mode for exactly that situation: **delegation mode**. OCR
performs the deterministic engineering (file selection, exclusion reasons, rule
resolution) and the host agent performs the semantic review with its own model. The review
therefore remains governed by OCR's own file accounting and rule set, and the hosted layer
is never claimed.

### Dispositions

**OCR-001 and OCR-002 are fixed at the reviewed head, not waived.** The repair adds
deterministic rejection of unknown keys at node, edge, state, and revision-document level
and rewrites `compareText` without a nested ternary. Canonical revision identity for
well-formed v1 documents is provably unchanged (identical probe digest before and after),
so the repair closes an identity-collision class without perturbing legitimate
equivalence.

**OCR-003 and OCR-004 are non-material hardening candidates**, accepted as risk for this
Grain because ADR-0003 explicitly defers large-graph performance until workload evidence
exists and because the canonical read path is `JSON.parse` output, which cannot be
cyclic. They are recorded for the follow-up P02-S02 grain rather than widening SG-000019
beyond its declared scope.

Two further observations were triaged out and are recorded for transparency: the empty
slice returned for an unknown node is deliberate and pinned by tests, and the query
session exposing no revision accessor is a deliberate minimal surface at this Grain.
