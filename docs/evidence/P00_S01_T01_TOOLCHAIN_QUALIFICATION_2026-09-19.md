### 4.2 First gate run — two real failures, not green

```text
$ npx tsc --noEmit -p tsconfig.json      -> exit 0
$ npx eslint .                           -> exit 1
  eslint.config.js  0:0  error  Parsing error: ... was not found by the project service.
$ npx prettier --check .                 -> exit 1 (7 files)
$ npx vitest run                         -> exit 1 (1 failed)
  expected 1, received 2
```

Two causes were found and fixed; neither was a toolchain defect:

1. The ESLint config file was covered by no TypeScript project. Fixed with
   `projectService.allowDefaultProject`; the gate was re-run and then passed.
2. The qualification test assertion was wrong (the function sums digits; `IN-P00-S01-T01`
   contains `1` and `1`, i.e. `2`). The oracle was corrected, not the code under test.

The originally failing run is preserved here rather than replaced by the later green run.

## 5. Candidate rejections

- TypeScript `7.0.2` — outside the declared `typescript-eslint` support range (see §3).
- npm workspaces — would create a second lockfile authority beside the qualified manager.
- Bun — not installed on the qualification host; adds a second runtime and lockfile format.
- Biome — cannot provide the type-aware ESLint rules the project requires.
- Turborepo / Nx — no task-graph evidence yet.

## 7. Result

The pinned baseline is installable, reproducible with a frozen lockfile, and its gates fail on real
defects. Versions, reasons, rejected alternatives, and revisit triggers are recorded in
`docs/adr/ADR-0001-p00-toolchain-baseline.md`; the supported procedure is
`docs/engineering/TOOLCHAIN.md`.
| `eslint` latest | `10.11.0`; engines `^20.19.0 \|\| ^22.13.0 \|\| >=24` | npm version metadata |
| `vitest` latest | `5.0.1`; engines `^22.12.0 \|\| ^24.0.0 \|\| >=26.0.0`; `vite` is a required peer | npm version metadata |
| `vite` latest | `8.3.0` | npm dist-tags |
| `prettier` latest | `3.9.8`; engines `>=14` | npm version metadata |
| `@types/node` latest | `26.6.2` (tracks Node 26) | npm dist-tags |

The decisive incompatibility: **TypeScript 7.0.2 cannot be paired with typed linting**, because
`typescript-eslint@8.70.0` declares `typescript >=4.8.4 <6.1.0`. The baseline therefore pins
TypeScript `6.0.3` instead of the npm `latest`.
